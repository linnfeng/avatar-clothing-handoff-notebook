# Avatar clothing handoff notebook

These are project-associated, AI-assisted documentation notes, not an independent product test or a report of customer outcomes. This repository contains a Markdown notebook for handing over avatar-clothing design work. It does not ship an editor, an exporter, a PNG validator or a Roblox publishing integration. The tables and examples below are templates for a review conversation, not evidence that a particular garment passed a technical or platform review.

![Official social preview for the independent browser studio](https://rbxshirtmaker.com/og.png)

## Why keep a handoff note?

A clothing image can look finished while the information needed for the next edit is missing. Someone receives a PNG, asks for a small lettering change, and discovers that the useful layers were kept in a different project. Another person sees a preview and assumes that an upload has already been approved. A short handoff note gives these different artifacts their own names and makes the remaining work visible.

The notebook is deliberately small. It can accompany a project backup and an image export without requiring a new account, a tracking service or an elaborate approval system. Use the parts that answer a real question and delete the rest from your own copy. A useful note should reduce uncertainty; it should not become an excuse to collect unnecessary personal information or invent reassuring completion claims.

## Choose the garment before naming the files

Start by identifying the intended format: a classic shirt, classic pants or a graphic T-shirt. Similar names do not make their layouts interchangeable. In the associated browser studio, classic shirts and pants export 585 by 559 PNGs with their respective garment regions, while graphic T-shirts export transparent 512 by 512 graphics. Record the intended format rather than assuming that any rectangular image can be stretched into the right result.

Dimensions alone do not settle the artwork question. An image can have the expected size while placing important details across an unwanted region. It can also have the expected size without resolving ownership rights, intact image data or destination-platform requirements. Treat a format note as one bounded piece of information, not a substitute for inspecting the image and following the destination's actual process.

## Give every artifact a role

An editable project preserves work that may need changing. A PNG is a finished image for a later workflow. A reference helps communicate an idea. A preview shows an arrangement from a particular viewpoint. These roles may concern the same outfit, but they are not the same promise. Keep separate labels even if all four files happen to share a similar thumbnail.

In particular, do not rename an exported image as a backup and expect the original editing state to reappear. Keep the project's editable form when the tool offers one, and check how it is meant to be reopened. A file available in one browser is not, by itself, evidence of cloud synchronization or recovery on another device. Note the save mechanism you actually used instead of assuming a service exists.

## Copyable inventory

| Field | What to record | What not to imply |
| --- | --- | --- |
| Artifact role | Project, export, reference or preview | That one file replaces every other role |
| Format | Intended garment and image arrangement | That dimensions certify artwork or approval |
| Revision | A short version label and reason | That the newest filename is necessarily best |
| Location | A recipient-usable relative path | That a private local path is publicly accessible |
| Observation | What was actually inspected | That an unperformed test succeeded |
| Open question | A specific remaining check | That silence means nothing remains |

Keep the inventory beside the artifacts rather than hiding it in a message that the next person may never receive. Relative paths can be useful within a shared folder, but check what the recipient actually has. Do not put a personal home-directory path, a session link, a password or an account token into a public issue or repository. A readable filename is normally enough to identify an example in a public discussion.

## A hypothetical package

Imagine a small club preparing a geometric shirt design. The package could contain an editable project, an exported image and a short review note. The note might distinguish an initial arrangement from a lettering revision and a later margin revision. Those labels describe a hypothetical exercise; they are not a report of a real club, a verified export or a successful Roblox upload.

The useful question is what the next person needs to change. If the lettering may move again, retain the editable work. If someone only needs to inspect the exported image, do not send unrelated references or private working material. A tidy handoff is not necessarily the largest possible archive. It is the smallest understandable set of artifacts that supports the agreed next step.

## Review one uncertainty at a time

Write a concrete question before making a revision. For example, ask whether lettering remains readable at the intended presentation size or whether a stripe crosses an unintended panel boundary. Save the previous version, make a limited change, and compare the result with that question in mind. A different-looking output is not automatically an answer to the original problem.

Compare the flat arrangement and an available preview without confusing either with certification. The associated studio offers an R6 preview, which can help someone inspect placement. A preview is still an observation with limits. Describe the particular view and the issue you noticed, and leave unchecked configurations in the open-question column. Do not turn a limited inspection into a universal fit or moderation guarantee.

## Use feedback that another person can understand

Avoid feedback that only says to change the green bit or make it look better. Name the affected region, describe the intended change, and distinguish a placement problem from a style preference. A short written note can help people who interpret colors differently or who are looking at a smaller display. These communication choices do not constitute an accessibility audit of the tool or the garment.

When several people comment, keep decisions attached to the relevant revision. If a suggestion was intentionally deferred, say so. That avoids asking a later editor to reverse a deliberate choice because its reason disappeared. It also makes it easier to stop: the group can identify which question has been answered rather than generating more alternatives simply because another generation is available.

## Keep AI optional and rights explicit

Use direct editing when it addresses the question more simply. An AI request can provide material to inspect, but it does not guarantee correct lettering, consistent regions or adherence to a reference. Preserve an earlier version before replacing a useful arrangement. No particular model provider, proprietary benchmark or model integration is claimed by this notebook.

Use references you are entitled to use and avoid unnecessary identifying details. An abstract shape may communicate a layout without uploading a participant's portrait or a confidential document. Generation does not make unclear rights disappear. Likewise, a convincing result does not automatically authorize distribution. The review note should describe the permissions you actually have rather than silently assuming every input and output is cleared.

## Free editing and separate downstream steps

The associated Roblox Shirt Maker workflow includes browser templates, PNG imports, direct editing, optional AI generation, an R6 preview and image downloads. Core editing, previews, project saving and downloads are free. Optional AI generation and revision use account credits, and the site's pricing page offers subscriptions and one-time credit packs. Check current offers rather than treating an introductory allowance as unlimited recurring access.

Roblox Shirt Maker is independent and not affiliated with Roblox. Exporting an image does not upload or approve clothing there. Roblox's own requirements, possible fees and moderation are separate from this notebook and the image editor. A handoff should identify which stage has actually occurred, especially when another person is expected to handle the destination-platform step later.

## Stop with a clear next action

Before sending the package, identify the intended garment, the editable version, the image export and the important remaining question. Confirm that the recipient can access the files you mention and that no unnecessary personal or credential information is included. Keep any claim about checks narrow enough that another person can understand what happened without guessing what was left untested.

The goal is not an endless checklist or a promise of perfect results. It is a handoff that another person can act on: understandable artifacts, a reason for the current revision, an honest record of observations and a proportionate next step. That is more useful than treating a polished screenshot, an editable project and an approved publication as interchangeable things.
